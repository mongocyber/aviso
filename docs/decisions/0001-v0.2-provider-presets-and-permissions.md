# V02-002 Provider Presets And Permissions

Status: Accepted historical v0.2 decision / rebaselined on 2026-06-12. Provider configuration support now exists for DeepSeek, Kimi / Moonshot, OpenRouter, Gemini, and Tencent Hunyuan in the current implementation candidate; live provider validation is still not started.
Date: 2026-06-11
Amended: 2026-06-12
Decision owner assumption: Owner approved entering V02-002 decision work. The default first implementation candidate was a small BYOK direct-provider batch: DeepSeek plus Kimi / Moonshot. On 2026-06-12, owner/CTO delegation selected OpenRouter as an additional BYOK OpenAI-compatible provider preset. Custom OpenAI-compatible base URL remains deferred to a separate optional-permission design.

## Context

Aviso is currently a Chrome MV3 BYOK direct-provider extension. Users provide their own API keys, and the extension calls approved provider hosts directly from the browser extension.

At the time of the original V02-002 decision, source and manifest scope was:

- Implemented provider ids: OpenAI, Anthropic, and Doubao / Volcengine Ark.
- Current host permissions: `https://api.openai.com/*`, `https://api.anthropic.com/*`, and `https://ark.cn-beijing.volces.com/*`.
- API keys stay in `chrome.storage.local/contextai_api_keys`.
- Non-secret settings stay in `chrome.storage.sync/contextai_settings`.
- No Aviso backend, provider proxy, hosted Aviso AI, login, subscription, payment, quota, telemetry, analytics, remote link-body fetching, web search, or storage-key migration is approved by this record.

Current implementation baseline is now tracked in `docs/archive/v0.2/v0.2-status.md`: DeepSeek has summary-only owner-manual connectivity pass evidence from 2026-06-12; Kimi / Moonshot, OpenRouter, Gemini, and Tencent Hunyuan have configuration support only or non-live validation evidence, with no broad live provider validation.

This decision follows the V02-001 provider architecture preflight recommendation to start provider expansion with a small OpenAI-compatible direct-provider batch after WXT parity, exact host-permission approval, and separate implementation review.

## Decision

V02-002 approved only the first-batch provider preset decision and the exact host-permission candidates for the V02-004 implementation line.

The decision record itself did not modify `package.json`, Plasmo manifest config, source code, storage keys, tests, README, STATUS, release checklist, website copy, or public store copy. Current implementation/status evidence is tracked in `docs/archive/v0.2/v0.2-status.md` and `docs/archive/v0.2/v0.2-issue-plan.md`.

## Custom Endpoint Decision

Custom OpenAI-compatible base URL is deferred.

Reason:

- Arbitrary user-provided base URLs require a separate Chrome optional host permission design.
- V02-004 must not add broad wildcard permissions, `<all_urls>`, or a catch-all custom endpoint permission.
- Custom endpoint UI, origin validation, permission prompts, failure states, help copy, and Chrome Web Store review impact need a separate decision record before implementation.

## Stop Lines

Stop and return to owner / CTO review before any thread attempts:

- Real provider calls or live connectivity tests.
- Reading, printing, logging, storing, or documenting API keys.
- Raw prompt, raw provider response, private page body, screenshots/base64, full URLs, or clipboard content in docs, logs, tests, release artifacts, or public copy.
- Any host permission beyond the currently approved provider hosts, including `https://api.deepseek.com/*`, `https://api.moonshot.cn/*`, `https://openrouter.ai/*`, `https://generativelanguage.googleapis.com/*`, and `https://api.hunyuan.cloud.tencent.com/*`.
- Adding broad wildcard permissions, `<all_urls>`, or arbitrary custom endpoint access.
- Custom endpoint implementation.
- Backend, provider proxy, hosted Aviso AI, login, subscription, payment, quota, telemetry, analytics, remote link-body fetching, or web search.
- Public claims that DeepSeek, Kimi / Moonshot, OpenRouter, Gemini, Tencent Hunyuan, Qwen, or any other v0.2 candidate is available, working, verified, release ready, or live validated before the corresponding evidence exists.
