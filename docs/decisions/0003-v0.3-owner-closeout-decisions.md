# v0.3 Owner Closeout Decisions

Status: accepted
Date: 2026-06-18

## Context

Aviso v0.3 adds an optional hosted AI path while preserving the current BYOK direct-provider product. The backend repository has local mock implementation evidence, but the extension has not integrated the backend and hosted AI is not deployed.

These decisions define the first v0.3 execution boundary before frontend implementation starts.

## Decision

1. Backend status wording is confirmed: backend logic is implemented locally with mocks; it is not deployed, not staging, not production, and not live in the extension.
2. The first v0.3 release scope is BYOK plus free hosted AI only.
3. BYOK users must not be forced to sign in. Login is required only when the user chooses or falls into hosted AI.
4. The first execution phase is local mock / local backend only. It does not approve host-permission changes, staging deployment, production deployment, real provider calls, or real secrets.
5. Free quota may use the current development placeholder of 1,000,000 monthly tokens and 50,000 daily tokens for local development and test UI only. This number must not be used in public copy.
6. The frontend should use the logical model name `free-small`. The real upstream model route remains backend-configured and must be re-evaluated before release.
7. The first v0.3 release does not launch paid subscriptions. Billing may remain a backend mock seam; no real payment provider or public paid plan is approved.
8. Hosted privacy boundary is confirmed: hosted requests pass through Aviso backend and OpenRouter / downstream providers; Aviso backend must not persist raw prompt, raw response, page body, screenshot/base64, clipboard content, API keys, or full URLs. Metadata retention is 30 days.

## Consequences

- Frontend implementation can be planned against local backend integration only.
- No extension backend host permission is approved by this decision.
- No staging, production, real provider validation, Google OAuth live validation, Paddle/LemonSqueezy activation, or public hosted-AI claim is approved by this decision.
- Public website, privacy policy, Chrome Web Store wording, and store data disclosure must remain release-gated.
- Paid subscription UI should not be treated as first-release scope except for non-live placeholders required by local UX design.

## Follow-up

- Complete v0.3 requirements closeout.
- Review backend API contract and shared types before frontend implementation.
- Define hosted/BYOK UX states for local implementation.
- Create the first execution issue only after the contract and UX gates are reviewed.
