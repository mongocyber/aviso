## Purpose

This record closes the docs-only preflight for the next provider preset batch:

- Gemini
- Qwen / DashScope
- Tencent Hunyuan
- Zhipu GLM

This record now also tracks the V02-017 owner-approved subset and V02-018 non-live validation outcome: Gemini and Tencent Hunyuan were implemented as configuration-supported fixed presets after preflight, then validated through static/unit/typecheck/build evidence only and CTO accepted as configuration support only. This does not run live provider calls, read API keys, fetch model lists, implement Qwen / DashScope or Zhipu GLM, or approve release copy.

## Global Batch 2 Boundary

- Each provider must use a fixed preset, fixed base URL, and fixed Chrome host permission.
- OpenRouter is only an aggregator preset. It does not equal official vendor-direct support for Gemini, Qwen / DashScope, Tencent Hunyuan, or Zhipu GLM.
- Model ID policy is manual input only. Aviso must not call provider model-list or account-model APIs.
- Live validation status for all providers in this record is `not authorized / not performed`.
- Connectivity testing, if later implemented, remains a manual Popup action, one config at a time, using the fixed public short prompt and redacted summary only.
- Vision, reasoning, thinking, tool use, image, audio, web search, and provider-specific extra parameters remain disabled or gated until a separate provider/model capability decision and implementation exists.
- Any provider that cannot safely fit the shared OpenAI-compatible adapter must stop at preflight and move to a separate adapter decision.

## Preflight Conclusions

### Candidate For Shared OpenAI-Compatible Adapter

These moved into the owner-approved V02-017 implementation subset:

- Gemini: fixed direct preset with `https://generativelanguage.googleapis.com/v1beta/openai/`, configuration support only, with thinking/vision/provider-specific fields still disabled unless separately implemented.
- Tencent Hunyuan: fixed direct preset with `https://api.hunyuan.cloud.tencent.com/v1`, configuration support only, through the OpenAI-compatible bearer-key path, not native Tencent Cloud signed APIs.

These are now recorded in V02-018 as `completed_non_live_validation / cto_accepted` for configuration support only. The validation evidence is static/unit/typecheck/build evidence; it is not live provider validation.

### Deferred Pending Owner Policy

- Qwen / DashScope: official docs expose multiple region-specific base URLs. Aviso must choose one fixed preset host before implementation. The safest first candidate is Beijing only if the owner approves that region policy; otherwise the provider remains deferred.

### Needs Separate Adapter Decision / Unresolved

- Zhipu GLM: official docs confirm general HTTP endpoint and chat completions path, but this preflight did not confirm enough official OpenAI SDK compatibility to safely reuse the shared adapter. Keep it out of V02-017 shared-adapter implementation unless a separate route conformance decision closes.

## V02-017 Entry Conditions

- Implementation must not include custom base URL, arbitrary host input, optional host permission flow, model-list fetching, new SDK dependencies, live provider validation, API key handling changes, or storage-key migration.
