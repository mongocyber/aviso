# Aviso v0.2 WXT Migration Plan

Status: Automated parity complete / loaded-extension QA pending
Updated: 2026-06-11

## Decision

WXT migration should be handled as a v0.2 infrastructure track before provider implementation.

The recommended order is:

1. Run provider architecture preflight and WXT migration preflight.
2. Complete WXT migration and prove build / manifest / loaded-extension parity.
3. Start provider preset, permission, config, and adapter implementation on top of the WXT baseline.

This keeps provider expansion from landing on a build system that will immediately be replaced.

## Why This Order

- WXT migration touches the build system, manifest generation, entrypoints, content-script UI mounting, popup mounting, assets, i18n layout, package scripts, and TypeScript config.
- Provider expansion touches background routing, Popup provider settings, manifest host permissions, tests, and docs.
- Doing provider implementation first would create rework in the same files WXT migration must move or refactor.
- Provider architecture preflight is still safe before migration because it is docs-only and does not touch source files or permissions.

## Official WXT Migration Notes

Current WXT documentation says migration should:

- Generate a new vanilla WXT project and merge files one at a time.
- Install `wxt`.
- Extend `.wxt/tsconfig.json` from the project TypeScript config.
- Update package scripts and add `postinstall: wxt prepare`.
- Move entrypoints into `entrypoints/`.
- Move assets into `assets/` or `public/`.
- Move manifest content into `wxt.config.ts`.
- Convert Plasmo import / entrypoint syntax to Vite-compatible WXT syntax.
- Add WXT default exports such as `defineBackground` and `defineContentScript`.
- Compare final manifests and make sure permissions and host permissions are unchanged.

### V02-WXT-003 Entrypoint And Runtime Migration

Execution readiness: Build complete; pending V02-WXT-004 manifest/package parity and loaded-extension QA.

Goal:

Move runtime entrypoints from Plasmo conventions to WXT conventions while preserving current behavior.

Scope:

- Convert background to WXT `defineBackground`.
- Convert Popup to WXT HTML / React mount entrypoint.
- Convert content scripts to WXT `defineContentScript`.
- Replace Plasmo content-script UI mounting with WXT `createShadowRootUi` or equivalent WXT UI utilities.
- Replace Plasmo types such as `PlasmoCSConfig` and `PlasmoGetShadowHostId`.
- Preserve current host IDs and UI isolation expectations where possible.
- Keep `chrome.*` API usage unless a specific WXT / cross-browser decision approves `browser.*` conversion.
- Preserve existing storage keys, messages, runtime IDs, and user-facing behavior.

Allowed writes:

- `src/entrypoints/`
- `src/background/`
- `src/contents/`
- `src/popup.tsx`
- `src/popup/`
- `src/styles/`
- `src/types/`
- `src/utils/`
- `tests/unit.test.ts`
- `docs/archive/v0.2/v0.2-status.md`

Required reads:

- V02-WXT-001 and V02-WXT-002 outputs.
- Current background, popup, and all content scripts.
- WXT entrypoint and content-script UI docs.
- Existing unit tests.

Execution output:

- WXT runtime entrypoints compile through `npm run build:wxt`.
- Current runtime surfaces are preserved at build / manifest level; behavior still requires loaded-extension QA.
- Tests updated only for WXT entrypoint changes or removed Plasmo selectors.

Non-scope:

- No provider expansion.
- No API key storage migration.
- No new extension permissions.
- No new product features.
- No real provider calls.

Acceptance:

- Current entrypoints are represented in WXT through wrappers under `src/entrypoints/`.
- Popup, toolbar, floating panel, command palette, double-click menu, clipboard prompt, screenshot internal path, readability, and frame bridge are still present.
- Existing privacy and local-only boundaries are preserved.
- No source file contains secrets or raw provider evidence.

Stop lines:

- Content script UI cannot preserve isolation without significant redesign.
- Manifest parity fails due generated entrypoint shape.
- Existing behavior requires broad new permissions.
- Build requires a new dependency beyond WXT and required WXT peer needs.

Validation:

- `git diff --check`
- `npm test`
- `npx tsc --noEmit`
- `npm run build:wxt`
