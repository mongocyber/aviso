## Current Conclusion

V02-006 establishes a minimal speed baseline method and improves the visible waiting experience before the first provider chunk arrives.

Implemented behavior:

- Selection translate, selection explain, page summary, and follow-up routes can show earlier processing text in the floating panel or inline translation card.
- Slow first-token waits show an explicit provider-waiting state after the shared 2 second threshold.
- Local timing summaries can report coarse stage timing for trigger, floating-panel visibility, background receipt, provider start, first chunk, and done.
- Timing summaries are not persisted, uploaded, or used as telemetry.
- Timing summaries do not include raw prompt, raw response, private page body, screenshots/base64, full URLs, clipboard content, or API keys.
- Operation-level fast-model strategy is implemented for short text `translate`, `explain`, and `polish` requests when `settings.fastProviderConfigId` points to a saved provider config.
- Page context requests, page summaries, page translation, follow-up/custom long-context routes, image explain, and screenshot explain continue to use the default provider config route.
- If no fast provider config is selected or the selected config no longer exists, requests fall back to the default route. If the selected fast config exists but is missing a key or required model ID, the request uses that route and is blocked by the existing missing-key / missing-model guard instead of silently falling back.
- Reasoning/thinking controls are not part of the current v0.2 product scope and are not enabled in request payloads.

Not implemented:

- No real provider live sampling was run.
- No TTFT p50 / p95 result is claimed or required for current v0.2.
- No fake streaming, fake token, or placeholder model output was added.
- No disable-thinking, no-reasoning, deep-thinking, or reasoning-control UI switch was exposed.
- No new provider, host permission, storage key namespace, API key handling, backend, proxy, telemetry, or analytics behavior was added by this slice.

## Baseline Method

Measure these operations only if a future owner-opened sampling issue authorizes a live sampling run:

| Operation | Trigger | Context type | Input boundary |
| --- | --- | --- | --- |
| Selection translate | Selection toolbar or inline translation | `selection` | Selected text only. No page body, link URL, full page URL, screenshot, clipboard content, or prior context. |
| Selection explain | Selection toolbar or context menu | `selection` | Selected text only, within existing context budget. |
| Page summary | Context menu or command action | `page_summary` | Existing bounded page summary text only; no full URL in timing output. |
| Follow-up | Floating panel follow-up input | `follow_up` | User follow-up plus bounded recent conversation context. |

For each operation, record only the summary fields produced by `buildPerfSummary`:

| Field | Meaning | Privacy rule |
| --- | --- | --- |
| `trigger` | Approved trigger label such as `toolbar`, `context-menu`, `command-palette`, `follow-up`, or `inline-translation`. | Unknown values become `unknown`. |
| `provider` | Approved provider id. | Unknown values become `unknown`. |
| `model_or_endpoint` | Model or endpoint id after URL/base64 redaction. | URL-like or data-like values become redacted. |
| `input_size_bucket` | One of `0-500`, `501-2000`, `2001-5000`, `5001+`. | Raw input text is never included. |
| `context_type` | `selection`, `page_summary`, `image_explain`, `command`, `follow_up`, or `unknown`. | No private content. |
| `t_ui_visible_ms` | Time from trigger to visible result panel or card. | Milliseconds only. |
| `t_background_received_ms` | Time from trigger to background receipt. | Milliseconds only. |
| `t_provider_start_ms` | Time from trigger to provider request start. | Milliseconds only. |
| `t_first_chunk_ms` | Time from trigger to first provider text chunk. | Milliseconds only; `null` when absent. |
| `t_done_ms` | Time from trigger to completion. | Milliseconds only; `null` when absent. |
| `error_category` | Redacted category such as `none`, `missing_first_chunk`, `timeout`, `network_error`, or `provider_error`. | No raw provider error body. |

## Removed Reasoning Controls Boundary

V02-006 does not enable reasoning controls, and current v0.2 no longer carries reasoning/thinking request-parameter control as a requirement.

Current rule:

- Do not expose reasoning/thinking controls in UI.
- Do not send reasoning/thinking request parameters.
- Do not make public claims that Aviso controls model reasoning/thinking.
- Future work requires a new owner-opened version or issue.

This keeps provider latency claims honest: Aviso can improve visible waiting states and measure timing, but it does not claim to disable provider thinking or solve real TTFT.
