## Non-Goals

This contract does not approve:

- Real provider calls by an execution agent.
- Reading, printing, logging, storing, or documenting API keys.
- Raw prompt, raw provider response, private page body, screenshots/base64, full URLs, or clipboard content in logs, docs, tests, release artifacts, or public copy.
- New backend, proxy, hosted Aviso AI, login, subscription, payment, quota, telemetry, analytics, remote link-body fetching, or web search.
- Custom OpenAI-compatible base URLs or broad wildcard host permissions in current v0.2.
- Arbitrary provider-host entry that bypasses fixed preset / fixed base URL / fixed host permission review.
- Storage namespace migration from `contextai_*` to another namespace.
- Public claims that DeepSeek, Kimi / Moonshot, OpenRouter, Gemini, Tencent Hunyuan, or any other v0.2 candidate is working, verified, release ready, or live validated beyond the available configuration-support evidence.

## Provider Config Schema Contract

### Current Persistent Shape

Provider config metadata is non-secret and remains in `chrome.storage.sync/contextai_settings`.

Sync fields:

| Field | Type | Contract |
| --- | --- | --- |
| `defaultProviderConfigId` | `string` | Optional selected config id. The default AI route should prefer this when present and valid. |
| `fastProviderConfigId` | `string` | Optional selected config id for short text fast-task routing. Empty means the fast strategy is disabled. If the id no longer resolves, runtime falls back to the default route; if it resolves but is missing key/model, existing pre-provider guards must block instead of silently falling back. |
| `providerConfigs` | `ProviderConfig[]` | Non-secret provider config instances. Must not contain API keys, raw prompts, raw responses, page bodies, screenshots/base64, full URLs, or clipboard content. |
| `defaultModel` | `string` | Legacy/current compatibility field. It may mirror the selected provider config model for existing menu and route behavior. |
| `doubaoModel` | `string` | Legacy/current Doubao endpoint/model field. Keep for compatibility with existing Doubao routes and legacy configs. |

`ProviderConfig` fields:

| Field | Type | Contract |
| --- | --- | --- |
| `id` | `string` | Stable config id, for example `cfg-<provider>-<random>` or legacy ids `legacy-openai`, `legacy-anthropic`, `legacy-doubao`. Used as the safe routing axis. |
| `provider` | provider id | Current documented ids are `openai`, `anthropic`, `doubao`, `deepseek`, `moonshot`, `openrouter`, `gemini`, and `hunyuan`. Future provider ids must remain curated vendor ids, not arbitrary custom-host aliases. DeepSeek, Moonshot, OpenRouter, Gemini, and Tencent Hunyuan remain configuration-support only without live validation. |
| `displayName` | `string` | User-visible config name. Empty input should fall back to provider display name plus index. |
| `model` | `string` | Manual model id or provider-specific endpoint/model value. Aviso must not call list-models APIs. |
| `isDefault` | `boolean` | Optional UI marker. `defaultProviderConfigId` remains the primary persisted default selection. |
| `testStatus` | `untested | success | failure` | Last manual connectivity state for the same provider and model. Defaults to `untested`. |
| `testErrorCategory` | `string` | Redacted error category only. No raw provider error body. |
| `testProvider` | provider id | Provider id used for the last test. Used to invalidate stale results. |
| `testModel` | `string` | Model/endpoint used for the last test. Used to invalidate stale results. |
| `testedAt` | `number` | Timestamp for the last manual connectivity test. |
| `createdAt` | `number` | Config creation timestamp. |
| `updatedAt` | `number` | Config update timestamp. |

API key material remains secret-like and local-only in `chrome.storage.local/contextai_api_keys`.

Local fields:

| Field | Type | Contract |
| --- | --- | --- |
| `openai` | encrypted string | Legacy OpenAI API key slot. Keep readable for compatibility. |
| `anthropic` | encrypted string | Legacy Anthropic API key slot. Keep readable for compatibility. |
| `doubao` | encrypted string | Legacy Doubao / Ark API key slot. Keep readable for compatibility. |
| `providerConfigKeys` | `Record<configId, encrypted string>` | Per-config API keys. New config instances, including DeepSeek, Kimi, OpenRouter, Gemini, and Tencent Hunyuan configs, must use this map instead of sync storage. |

Deletion behavior:

- Saving an empty key should delete that local key entry instead of storing an empty encrypted value.
- Deleting a provider config should also delete its `providerConfigKeys[configId]` entry.
- Legacy config deletion may clear the legacy provider key and existing legacy endpoint setting, but must not migrate the storage namespace.

### Loose-Save Acceptance Boundary

Current accepted save boundary:

- Saving a provider config does not require a successful live connectivity test first.
- Saving a provider config does not upgrade that config to validated/verified status.
- Missing required API key or required model/endpoint must still produce blocked state and must not allow a real provider call.
- Manual connectivity remains an explicit user action, one config at a time, with redacted summary only.

This boundary should be treated as an accepted product behavior note for the current implementation candidate, not as evidence of provider availability.

## UI State And Copy Contract

UI copy should stay natural and operational. It must not make public-release or live-validation claims.

| State | Data condition | UI behavior | Current copy basis |
| --- | --- | --- | --- |
| Not configured | No key, or required model/endpoint missing. | Show blocked/danger state. Do not call provider. Prompt user to save key and model/endpoint. | `尚未配置` / `Not configured`, `未配置 Key` / `Key missing`. |
| Configured / untested | Key and required model/endpoint exist, but no current test result. | Allow selection/use where current product permits, but label as untested or recommended to test. Do not imply verified. | `未测试` / `Untested`, `建议测试` / `Test recommended`. |
| Test passed | `testStatus: success` and `testProvider` / `testModel` still match current config. | Show green/ok status and redacted summary. This means one manual connectivity test passed, not public release validation. | `上次通过` / `Last passed`, `连接测试通过` / `Connection test passed`. |
| Test failed | Current or last summary has `result: failure`. | Show danger state and error category. Do not show raw provider error text. Selected route should surface service failure until config changes or retest passes. | `上次失败` / `Last failed`, `连接测试未通过` / `Connection test failed`. |
| Endpoint/model missing | Provider requires model/endpoint and config value is empty. | Show blocked state. Save/test should return redacted preflight summary and not call provider. | `未配置接入点` / `Endpoint missing`, `接入点缺失` / `Endpoint required`. |
| Unsupported capability | Requested feature is unsupported or only model-dependent and unvalidated, such as screenshot vision for model-dependent providers or removed/out-of-scope reasoning controls. | Block before provider call. Show a capability-specific user message. Do not send private payload to probe support. | Existing screenshot vision gate blocks model-dependent Doubao image route. |
| Default config | `defaultProviderConfigId` matches config id, or default resolver selects it. | Show default pill and disable redundant "set default" action. | `默认` / `Default`. |
| Editing / unsaved | Config mode is `add` or `edit`, or key/model/name changed locally. | Show adding/editing and unsaved pills. Retain old saved state until user saves or cancels. Clear stale connectivity result when provider, model, or key changes. | `新增中` / `Adding`, `编辑中` / `Editing`, `未保存` / `Unsaved`, `等待保存` / `Waiting to save`. |

UI rules:

- API key inputs may display only masked suffix, for example `********1234`; never render full keys.
- The manual model hint must remain clear: users enter a model id manually and Aviso does not fetch their account model list.
- Provider picker copy must make it clear that users are selecting a named vendor preset, not a generic arbitrary endpoint.
- A failed or missing configuration should not be described as "provider unsupported" unless the issue is actually a capability gate.
- "Supports configuration" is the strongest allowed wording for DeepSeek / Kimi / OpenRouter / Gemini / Tencent Hunyuan without owner-approved live validation.

## Routing Contract

Routing should use provider config instances, not provider type alone.

Required route inputs:

- `providerConfigId` when the user selected a saved config instance.
- `provider` id from the config or registry.
- Manual model id from `ProviderConfig.model`, or legacy `doubaoModel` where compatibility requires it.
- Fixed provider `baseURL` from provider registry metadata for OpenAI-compatible providers.
- Capability flags from provider/model metadata.

Required route outputs:

| Field | Contract |
| --- | --- |
| `providerConfigId` | Present when route is derived from a provider config. Used to retrieve `providerConfigKeys[configId]` without exposing secrets. |
| `provider` | Provider registry metadata, including `displayName`, `sdk`, `hostPermission`, and optional `baseURL`. |
| `selectedModel` | UI-selected model id or config model alias. |
| `requestModel` | Exact model/endpoint string sent to provider. Must be non-empty before a provider call. |
| `model` | Model metadata or fallback metadata for manual ids. |
| `missingConfig` | Set when required endpoint/model is missing. DeepSeek/Kimi/OpenRouter/Gemini/Tencent Hunyuan manual model input must block provider calls when empty. |
| `isFallback` | True when the model id is not in the static model registry. Manual model ids may be fallback routes. |

Routing rules:

- Use `providerConfigId` as the safe routing axis for Popup actions, context menu default selection, background AI calls, and manual connectivity tests.
- `fastProviderConfigId` is only an operation-level override for short text `translate`, `explain`, and `polish` requests outside page/image/screenshot contexts. It does not change the default service or context-menu model radio semantics.
- Missing or stale `fastProviderConfigId` falls back to the default route; an existing fast config with missing API key or required model ID must fail through the existing missing-key / missing-model guards rather than falling back.
- Use `providerConfigKeys[configId]` for non-legacy config API keys; use legacy key slots only for legacy config ids.
- Use provider registry `baseURL` for OpenAI-compatible providers. Do not store arbitrary base URLs in sync settings for the first batch.
- Future batch-2 presets must also route through registry-owned fixed base URLs. User-provided provider hosts remain out of scope.
- Do not call list-models or account-model APIs.
- Manual model ids are allowed, but empty required model ids must stop before provider call.
- Vision controls must be gated by provider and model metadata. Do not infer support from provider name alone.
- `vision: model-dependent` must not automatically enable screenshot/image routes. Existing screenshot privacy and capability gates still apply.
- `reasoningControl` is removed from current v0.2 scope. Do not add provider/model reasoning UI, speed claims, or request parameters without a new owner-opened version or issue.
- Unknown model compatibility should continue to preserve current behavior: `claude*` routes to Anthropic, Doubao routes to Ark when selected/configured, and other unknown text models fall back to OpenAI-compatible OpenAI behavior unless a provider config route explicitly overrides it.

## Redacted Connectivity Summary Contract

Connectivity tests are manual safety checks, not background scans or release validation.

Rules:

- Trigger only from a user action in Popup.
- Test one config at a time.
- Do not auto-test all providers on settings open, install, update, or build.
- Use the fixed public prompt only: `请用一句中文回答：连接测试成功。`
- Do not include selection text, prior context, page content, link URL, image URL, page URL, screenshot/base64, clipboard content, template id, or private user data in the test payload.
- Do not log or display API keys, raw prompts, raw provider responses, raw provider error bodies, private page text, screenshots/base64, full URLs, or clipboard content.

Summary fields:

| Field | Contract |
| --- | --- |
| `provider` | Provider id tested. |
| `model_or_endpoint` | Model id or endpoint/model string tested. |
| `action` | Always `provider_connectivity_test`. |
| `trigger` | Always `manual_settings_provider_button`. |
| `host_permission_present` | Boolean from manifest host permission check. |
| `result` | `success` or `failure`. |
| `latency_note` | Human-readable redacted summary. Prefer coarse bucket/summary wording such as not started, under 1s, 1-3s, 3-10s, timeout, or failed after request; no raw trace. |
| `error_category` | Redacted category only. |
| `secret_leak_check` | Always `pass` for valid summaries. |
| `raw_prompt_logged` | Always `no`. |
| `raw_response_logged` | Always `no`. |
| `private_page_data_logged` | Always `no`. |
| `notes` | Short sanitized explanation. No raw provider response or private data. |

Allowed error categories:

- `none`
- `api_key_missing`
- `endpoint_or_model_missing`
- `host_permission_missing`
- `unauthorized`
- `rate_limited`
- `network_error`
- `timeout`
- `provider_error`
- `unknown_error`

Capability blocks such as unsupported image input or removed/out-of-scope reasoning controls should be represented as feature-route gates before provider calls. They should not be converted into live connectivity probes.

## API Key Storage Behavior

Storage behavior remains unchanged:

- API keys stay in encrypted form in `chrome.storage.local/contextai_api_keys`.
- New per-config API keys stay in `contextai_api_keys.providerConfigKeys[configId]`.
- Non-secret provider configs stay in `chrome.storage.sync/contextai_settings.providerConfigs`.
- Default selection stays in `chrome.storage.sync/contextai_settings.defaultProviderConfigId`.
- API keys must not enter `chrome.storage.sync`, docs, tests, console output, telemetry, release artifacts, or public copy.
- No `contextai_*` storage key migration is approved in V02-003 or implied by the current provider expansion baseline.

Security wording remains:

- Current key protection is local encryption / obfuscation-level protection derived from the extension id.
- It does not defend against an attacker who can read the local browser profile or control the machine.
- Do not describe it as server-side security, account security, or project-owned key custody.
