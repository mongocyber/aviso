## Summary

V02-007 adds deterministic local intent handling to the command palette while keeping Aviso a confirm-first browser assistant, not an autonomous browsing agent.

Implemented local behavior:

- `open` / `打开` URL intent creates an open-URL candidate and only opens it after the user selects the candidate.
- Browser history search remains local and only returns safe `http` / `https` candidates.
- Bookmark search remains local and only returns safe `http` / `https` candidates.
- Aviso local AI conversation search remains local. Selecting a conversation restores saved local messages in the result panel and does not re-send the conversation to a provider.
- `translate current page` / `翻译当前页面` creates a current-page candidate. Selecting it reads the current page through the existing content extraction path and starts a normal provider-backed result panel request.
- `summarize current page` / `总结当前页面` creates a current-page candidate. Selecting it reads the current page through the existing content extraction path and starts the existing page-summary request.
- `ask ai` / `问 AI` creates an AI candidate. Selecting it uses the existing provider path only for the user's typed question.

## Safety Boundaries

- No new permissions, host permissions, dependencies, backend, provider proxy, web search, remote link-body fetching, or browser automation were added.
- Unsafe and internal URL schemes are blocked or not offered as candidates: `javascript:`, `data:`, `file:`, `chrome:`, `chrome-extension:`, `about:`, and `blob:`.
- History, bookmarks, and local conversation candidates are not automatically sent to a provider.
- Page translate and page summarize require an explicit command-palette candidate selection before page content is read and sent to the configured provider.
- Selecting a saved AI conversation uses the result panel restore path and does not create a new AI request.
- All open, navigation, and current-page actions remain confirm-first in the v0.2 requirement baseline.
