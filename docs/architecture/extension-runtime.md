# Extension Runtime Contract

## Responsibility

The runtime is a Chrome MV3 extension with Plasmo kept for local dev/build compatibility and WXT used for the canonical release package. Package/version and manifest boundaries are release-sensitive; current release status lives in [docs/STATE.md](../STATE.md).

## Key Files

- `package.json:7` defines scripts for dev, builds, docs check, release verification, and packaging.
- `package.json:50` holds the extension manifest source, including permissions and host permissions.
- `src/entrypoints/background.ts:3` uses WXT `defineBackground` and imports the background service worker.
- `scripts/package-production.mjs:13` defines `.output/chrome-mv3` as the intermediate WXT output and `build/chrome-mv3-prod` / `build/chrome-mv3-prod.zip` as canonical owner-loaded artifacts.
- `scripts/verify-release-candidate.mjs:13` sequences tests, typecheck, WXT build, Plasmo build, canonical package, manifest checks, claim scan, and artifact hygiene.

## Invariants

- Do not load `.output/chrome-mv3` as the owner release candidate; it is only an intermediate WXT build output.
- `build/chrome-mv3-prod` must be regenerated by `npm run package` before release-package evidence is trusted.
- Manifest permissions and host permissions are owner-gated; adding or widening either requires explicit approval and docs updates.
- Plasmo remains the local dev/build rollback path; WXT remains the canonical release package path unless an owner-approved decision changes it.

## Extension Points

- Add or change extension entrypoints under `src/entrypoints/`, then update package/manifest checks and [testing.md](./testing.md).
- Release package changes belong in `scripts/package-production.mjs` and must preserve the stable extension ID key injection.
- Release-candidate verification changes belong in `scripts/verify-release-candidate.mjs`.

## Checks

```bash
npm run docs:check
npm run check:manifests
npm run package
```

Use `npm run verify:release-candidate` only when full release-candidate evidence is needed; it runs heavier build and package checks and must not be described as CWS approval.
